## PR #1 — `## Audience` section (personas)

**Titel**: `spec: add optional Audience section (personas)`

**Body**:

> Every AI agent that writes copy needs to know who it's talking to — audience is arguably the highest-value brand context after voice. This PR adds an optional `## Audience` section: one `###` subsection per persona with a short profile line, primary goal, key traits and an optional in-their-words quote.
>
> It's fully additive: parsers that don't know the section skip it. We've implemented this in a generator + emitter and shipped example files; happy to adjust naming/shape to whatever you prefer.
>
> Example:
>
> ```markdown
> ## Audience
>
> ### Ritual Rosa
>
> Home-brew perfectionist, 28-40
>
> - Primary goal: Cafe-level coffee at home
> - Key traits: curious, quality-driven
> - In their words: "Tell me the farm, not the vibe."
> ```

## PR #2 — `provenance` frontmatter

**Titel**: `spec: add optional provenance frontmatter (generated_by / generated_at / canonical / source)`

**Body**:

> brand.md files will be generated by tools and then travel — into repos, briefs and chats. Without provenance a reader can't tell how old a file is or where the living version lives, so files silently go stale.
>
> This PR adds an optional `provenance` frontmatter block: `generated_by`, `generated_at` (ISO date), optional `canonical` (URL of the maintained version) and optional `source` (the site a generator scanned). Additive; unknown frontmatter keys are already ignored by core parsers.
>
> ```yaml
> provenance:
>   generated_by: <tool or author>
>   generated_at: "2026-08-03"
>   canonical: "https://example.com/acme/brand.md"
> ```

## PR #3 — structured `## Guardrails` (machine-checkable do/don't)

**Titel**: `spec: add optional structured Guardrails section`

**Body**:

> Guardrails are the part of a brand file that tools can actually *enforce* — but only if they're structured. This PR adds an optional `## Guardrails` section with `### Do` / `### Don't` bullet lists, so validators and agents can check output against concrete rules ("Avoid the word X") instead of prose.
>
> We ship a dependency-free validator that already reports this section; happy to contribute a reference check upstream too.
>
> ```markdown
> ## Guardrails
>
> ### Do
> - Name the farm and roast date
>
> ### Don't
> - Avoid the word/phrase "artisanal"
> ```
